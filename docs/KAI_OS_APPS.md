# Кастомные приложения K + AI OS

Платформа расширяется приложениями на `twenty-sdk`. Приложение — это
самостоятельный TypeScript-проект, который добавляет в рабочее пространство
свои объекты, серверную логику, элементы интерфейса и ИИ-агентов.

Важно для нас юридически: ядро под AGPLv3, но **SDK и всё, что на нём написано,
под MIT**, плюс действует «Twenty Application Exception» — приложение,
работающее через публичные интерфейсы (REST/GraphQL, вебхуки, манифест,
функции логики, front-компоненты, SDK), **не подпадает под AGPLv3** и может
лицензироваться как угодно, включая проприетарную лицензию. То есть наши
собственные отраслевые модули можно продавать закрытыми.

---

## 1. Что можно построить

| Тип сущности | Назначение |
|---|---|
| Objects | Свои объекты с типизированными полями, связи, расширение стандартных объектов |
| Logic functions | Серверный код: обработчики, HTTP-маршруты, фоновые задачи, key-value хранилище |
| Front components | React-компоненты, отрисовываемые внутри интерфейса |
| Skills & Agents | Навыки и агенты для ИИ-чата и рабочих процессов |
| Views, Navigation, Page layouts | Представления, пункты меню, макеты страниц записи |
| Command menu items | Свои команды в командном меню |

## 2. Разработка

Требуется Node.js 24.5+, Yarn 4 через Corepack и Docker.

```bash
npx create-twenty-app@latest my-kai-app
cd my-kai-app
yarn twenty docker:start
yarn twenty dev
```

`docker:start` поднимает локальный экземпляр на `localhost:2020` из образа
«всё-в-одном» — того самого `twenty-app-dev`, который мы отрезали от
продакшен-сборки. CLI сам авторизуется в предзаполненном демо-пространстве.

`yarn twenty dev` следит за `src/`, пересобирает и синхронизирует изменения с
сервером за секунды. Для CI есть одноразовые команды: `yarn twenty plan`
показывает предстоящие изменения метаданных, `yarn twenty apply` применяет их и
возвращает код выхода.

Чтобы разрабатывать против нашего боевого сервера, а не локального:

```bash
yarn twenty dev --url https://os.kai-it.pro
```

Авторизация пройдёт через OAuth.

## 3. Переводы в приложениях

Устроены **иначе, чем в ядре**: ядро использует `.po` и Lingui, приложения —
плоские JSON-каталоги в папке `locales/`.

Строки размечаются хелперами из `twenty-sdk/front-component`:

| Хелпер | Когда |
|---|---|
| `Trans` | статический текст в JSX |
| `useTranslate().t` | динамические строки, перерисовываются при смене языка |
| `t()` | строки в обработчиках событий и на уровне модуля |
| `msg()` | ленивые дескрипторы в конфигурационных объектах |

```bash
yarn twenty dev:translations-extract
```

Собирает и метки манифеста, и строки компонентов в `locales/en.json`, рядом
кладутся целевые локали — `locales/ru-RU.json`. Формат: строки без контекста
лежат плоско, строки с контекстом (включая все метки манифеста) — вложены под
ключом контекста.

```json
{
  "Deal stage": "Этап сделки",
  "opportunity": {
    "Stage": "Этап"
  }
}
```

Каталоги компилируются командой `twenty dev:build`, то есть после правки
переводов нужна пересборка. В рантайме компонент берёт язык из контекста
исполнения — текущего языка интерфейса — и при отсутствии перевода откатывается
на исходную строку.

**Для нас это значит:** каждое своё приложение надо сразу вести с
`locales/ru-RU.json`, иначе на русском интерфейсе его строки полезут
по-английски и сломают впечатление от демо.

## 4. Публикация

Два пути распространения.

**Тарболом** — приватно, внутри компании. Не попадает в каталог, ставится
напрямую. Наш основной вариант для клиентских внедрений.

**Через npm** — попадает в каталог маркетплейса и виден всем. Требует добавить
`"twenty-app"` в `keywords` в `package.json` (шаблон `create-twenty-app` его
не добавляет), после чего:

```bash
yarn twenty app:publish
```

Оформление карточки в каталоге задаётся в `defineApplication()`: логотип,
скриншоты галереи (пропорции 8:5, до 10 МБ), `author`, `category`, `websiteUrl`.

Подтверждение происхождения через npm trusted publishing настраивается
workflow-файлом `publish.yml` из шаблона плюс регистрацией репозитория на
npmjs.com в разделе Settings → Trusted Publisher. **npm принимает provenance
только из публичных репозиториев** — для приватных его надо отключить
переменной окружения.

Сервер синхронизирует каталог npm раз в час; немедленная синхронизация —
`yarn twenty dev:catalog-sync`.

Установка: Настройки → Приложения в интерфейсе, либо `yarn twenty app:install`.
